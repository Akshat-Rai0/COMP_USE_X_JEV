The four layers

  • Body
    Cua Driver reads the screen and acts
  • Reflex
    Jev picks the next control
  • Planner
    An LLM plans, writes text, and rescues
  • Verify
    Noul questions check the result

Roadmap

Twelve weeks from Sep 28 to Dec 20, shaped around the academic calendar: build the showable version before Nov 9, coast through the exam window, then harden, measure, and ship.

Week 0: this week

The phases

A. Spike (weeks 1 to 2, Sep 28 to Oct 11): find out what is actually true
Tasks
  • Dump the UI tree of 3 or 4 candidate apps and rate how usable each is as text.
  • Make a first Jev call with a Choice and a Noul question. Measure the round trip from Patna over 30 calls and record p50 and p95.
  • Try Choice questions with 50 and with 255 options to see how it behaves near the cap.
  • Decide D1 and D2. Write the DecisionBackend and Body interfaces with fakes.
Exit gate
The chosen app's UI tree reads well as text, latency is measured, and the hero task is chosen. If there is no Jev access by Oct 4, the LLM backend becomes the default until access lands.
Cut if behind
Nothing. This phase is the safety net.
B. Walking skeleton (weeks 3 to 4, Oct 12 to 25): the smallest loop that works
Tasks
  • Serializer v1, loop controller, and trace writer to SQLite with screenshots.
  • Choice and Noul through the backend interface; the LLM backend behind the same interface.
  • A static trace viewer: HTML generated from SQLite.
  • Record and replay tests using the fakes.
Exit gate
Calculator 6 × 7 succeeds 10 times out of 10, each with a complete trace.
Cut if behind
The trace viewer becomes a JSON dump.
Note
Week 3 has a quiz window and week 4 has the Durga Puja break, so keep week 3 light and use the holiday for the hard part.
C. Hero task and v0 video (weeks 5 to 6, Oct 26 to Nov 8)
Tasks
  • Serializer pruning to 255 elements; planner for plan, replan, and text.
  • Confidence gate, top-two gap gate, loop breaker, and risk gate.
  • The hero task end to end, with a code check on the real end state.
  • Record the v0 demo video.
Exit gate
The hero task completes end to end at least once, and the video is recorded before Nov 9.
Cut if behind
A second app; the approval screen becomes a terminal prompt.
Reduced-hours window (Nov 9 to Nov 25)
Allowed
Unattended repeatability runs in the background and short notes on failures.
Not allowed
New features.
Exit gate
None. Protect the exams.
D. Harden (Nov 26 to Dec 6)
Tasks
  • Tune the gates from the trace data.
  • Run 20 consecutive runs of the hero task and record the results.
  • Settle the sandbox (D3): dedicated user, and a Lume VM only if the Driver runs inside it.
  • Kill switch, budgets, and the top five failure causes.
Exit gate
20 consecutive runs measured, and the safety rules enforced by code and covered by tests.
Cut if behind
The Lume VM.
E. Console and evaluation (week 11, Dec 7 to 13)
Tasks
  • The live run console, batch results, and the calibration table (see UI).
  • Stretch: the LLM-only baseline on the same task.
Exit gate
Numbers exist for all five success measures, and the console shows a real run.
Cut if behind
The baseline, and React (use plain HTML).
F. Ship (week 12, Dec 14 to 20)
Tasks
  • README with measured numbers and a failure analysis.
  • Final demo video of about 90 seconds.
  • One resume bullet, using only numbers from your own runs.
Exit gate
The repo is public and the demo is linked from the resume.
Cut if behind
The write-up.

Cut lines

If time runs short, drop things in this order:

  1. The LLM-only baseline
  2. A second hero task
  3. The Lume VM
  4. The live console (fall back to the static trace viewer)
  5. The write-up

Never cut confidence gating, the Noul checks, trace logging, the safety rules, or honest metrics. They are the project.
